# 直播控制室 · 帧性能巡检台

一个在浏览器本地运行的**主线程帧性能巡检工作台**：向 16ms 帧预算的时间线中加入不同优先级、
预计耗时和可取消性的任务，观察它们如何争抢主线程，并自动标出**长任务、被推迟任务、取消结果
和掉帧帧号**。用于解释“一段复杂操作为什么会让直播画面掉帧”。

- **纯本地仿真**：无真实设备、无后端、无外部服务，不使用 `setTimeout`/随机数做模拟数据，
  调度完全由确定性函数计算。
- **技术栈**：React 18 + TypeScript（strict）+ Vite 5 + Vitest 2 + Testing Library。

## 运行方式

要求 Node.js ≥ 18。

```bash
npm install        # 安装依赖
npm run dev        # 启动开发服务器（默认 http://localhost:5173）
```

其他命令：

```bash
npm test           # 运行全部测试（一次性，CI 友好）
npm run test:watch # 监听模式
npm run build      # 类型检查 (tsc -b) + 生产构建到 dist/
npm run preview    # 本地预览生产构建
```

## 30 秒上手

1. `npm run dev` 打开页面，内置场景 **「切换直播画面」** 已就绪：
   帧 0 同时入队四路工作 —— 解码新机位关键帧（用户阻塞 14ms，不可取消）、
   重算画中画布局（高 12ms）、上报切台日志（普通 6ms）、
   预加载下一路信号（空闲 55ms，可取消）。
2. 点击 **播放 / 单步**，逐帧观察任务条如何落入 16ms 格子；默认配置下可见
   **4 次掉帧（帧 0、2、3、4）** 与一个 **55ms 长任务**，完成时间 87ms。
3. 点击场景横幅中的 **「取消预加载（第 0 帧）」**：掉帧立即降为 **1 次**、
   完成时间缩短到 **32ms**、长任务消失，巡检结论同步更新。
4. 在任务卡片中调整**优先级 / 耗时 / 入队帧 / 可取消性**，或切换顶栏
   **帧率预算（8/16/33ms）与长任务阈值（25/50/100ms）**，所有指标即时重算。
5. **重放**永远回到帧 0 并可逐帧复现完全相同的过程。

## 仿真模型（为什么这样判定）

- 时间被切成等长 vsync 帧，每帧主线程预算默认 **16ms（约 60fps）**。
- 任务**整块执行、运行到完成**（对齐 JS 单线程语义）：一旦开始就不可中断。
  因此所谓“抢占”只发生在任务开始之前——**高优先级任务只能推迟（defer）排队中的
  低优先级任务，无法抢占已经在运行的任务**。这是巡检台最想传达的一点。
- 每帧开始的处理顺序是确定的：新任务入队 → 取消命令生效 → 按
  **(优先级升序, 到达顺序 FIFO)** 调度；线程在帧 deadline 前变空闲就继续启动下一个任务，
  即使该任务会超出剩余预算（它会一直跑到完成）。
- **掉帧**：某帧 vsync deadline（帧末）时刻主线程仍被占用（严格超出），该帧无法提交。
  恰好打满预算记为“零余量”风险帧但不算掉帧。一个超长任务会让其跨越的每个后续帧连续掉帧。
- **长任务**：单次连续执行时长 ≥ 阈值（默认 50ms，对齐 `PerformanceObserver` longtask）。
- **取消**：只在任务**开始前**生效。结果分为
  `before-start`（成功移除）、`ignored-running`（已在同步执行中，运行到完成不可中断）、
  `ignored-not-cancelable`（任务声明不可取消）、`ignored-already-done`（已完成）、
  `ignored-unknown`（任务不存在）。
- **推迟**：任务在队列中每多等一个帧周期，其 `deferredFrames` 加 1。

### 确定性重放

引擎（`src/engine/scheduler.ts`）是无时钟、无随机数的纯函数。输入在
`normalizeInput` 中被拷贝并按稳定键排序，因此**任务和取消命令的数组书写顺序不影响结果**；
相同输入必得逐字节一致的输出（含事件序列），播放/单步/重放只是对同一份结果取前缀。

```
  scheduler.test.ts  帧预算 / 优先级 / 抢占 / 取消 / 长任务

```

## 测试覆盖

共 43 个测试，按需求五类组织：

- **帧预算**：恰好打满（0 空闲不掉帧）、超出 1ms 的连续掉帧、帧内连续调度、自定义 8ms 预算、非法输入校验。
- **优先级**：严格优先级序、同优先级 FIFO、推迟帧计数、新高优任务不能中断运行中的任务、
  只能挤走尚未开始的低优先级任务。
- **抢占/取消**：开始前取消成功、不可取消被忽略、跨帧执行中取消为 `ignored-running`、
  完成后取消为 `ignored-already-done`、未知任务为 `ignored-unknown`、取消排队中的长任务后后续帧不再阻塞。
- **长任务**：50ms 阈值边界（≥ 判定）、自定义阈值、跨越多 vsync 的连续掉帧与来源任务标注。
- **确定性重放**：重复运行逐字节一致、任务/取消命令乱序输入结果一致、不修改调用方数组、
  逐帧前缀一致、拒绝空/重复 id；另含内置场景在取消与改优先级前后的指标断言（4→1 掉帧、87→32ms）。
- **安全上限**：自然结束不误报、超长/被饿死任务触顶后状态与巡检结论正确、恰好在上限帧末结束不算触顶。

## 设计与可访问性

- 类别配色（解码/布局/日志/预加载/自定义）为固定的分类调色板，颜色跟随任务实体，
  调整参数不会让剩余任务“变色”；浅/深双模式均通过 CVD 相邻色差与对比度程序校验，
  浅色模式下低对比的青/黄/品红按规范以**直接标签 + 图例 + 数据表**补偿。
- 状态色（好/警告/严重）仅用于状态，并始终配有图标与文字，不单独依赖颜色。
- 时间线任务条 ≤24px、4px 圆角，提供悬停 tooltip、图例、纹理通道与表格视图。
